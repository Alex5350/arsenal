# Role agents library

Last verified: 2026-09. Agents are casted roles: a model, instructions, and
a scope of authority. The roles are defined once here; each harness receives
them through its own door. This is the same shape as the
[skills library](../skills/README.md): skills are procedural knowledge any
agent loads, agents are the roles themselves.

## The library

| Agent | Tier | Owns |
| --- | --- | --- |
| [`researcher`](researcher.md) | strategist | phase 01, cited findings via fan-out |
| [`planner`](planner.md) | strategist | phase 02, standalone implementation plans |
| [`reviewer`](reviewer.md) | reviewer | phase 04, gate evidence and diff verdicts |

The executor tier is deliberately not a file: your main session in every
harness already plays it, per [AGENTS.md](../../AGENTS.md) and
[models/routing.md](../models/routing.md).

## Doors

| Harness | Door | Mechanism |
| --- | --- | --- |
| Claude Code | `.claude/agents/<name>.md` | committed per-file symlink to `docs/agents/<name>.md` |
| OpenCode | `.opencode/agent/<name>.md` | committed per-file symlink |
| VS Code Copilot | `.github/chatmodes/<name>.chatmode.md` | committed per-file symlink |
| Codex CLI | `.codex/agents/<name>.toml` | generated by `scripts/bootstrap.sh` (TOML, gitignored) |

Per-file links, not directory links: harness scanners read these directories
verbatim and must see only agent files. Codex's format is TOML rather than
markdown, so its door is generated (with a "do not edit" header) and
regenerated on every bootstrap run.

## Authoring rules

1. **Frontmatter is the portable minimum**: `name` and `description` only.
   Every harness reads both; no harness chokes on the pair. Do NOT add
   `model`, `tools`, or `mode` keys: their value formats are per-harness and
   a shared file cannot carry per-door values. Model assignment lives in
   [models/routing.md](../models/routing.md); tool restriction is a per-door
   override a team applies by replacing a link with a real file when it
   truly needs one.
2. **The description is the trigger.** It states what the agent does and
   when to use it, because Claude Code and OpenCode auto-delegate based on
   descriptions. Write it with the same care as a skill description.
3. **The body is the role contract**: tier, phase, job, boundaries, links to
   the standards and skills it uses. Standalone and short (under ~60 lines):
   the agent may be spawned with nothing else in context.
4. **Adding an agent**: write `docs/agents/<name>.md`, run
   `scripts/bootstrap.sh` (it creates the three markdown door links; commit
   them) and `scripts/validate-agents.sh`, then PR per the loop.
5. Roles, not people-imitations. An agent file defines a job in the loop,
   never a persona with a name and a backstory.
