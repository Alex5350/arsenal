# Role agents library

Last verified: 2026-09. Agents are casted roles: a model, instructions, and
a scope of authority. The roles are defined once, in `.claude/agents/`;
this page is their contract. This is the same shape as the
[skills library](../skills/README.md): skills are procedural knowledge any
agent loads, agents are the roles themselves.

## The library

| Agent | Tier | Owns |
| --- | --- | --- |
| [`researcher`](../../.claude/agents/researcher.md) | strategist | phase 01, cited findings via fan-out |
| [`planner`](../../.claude/agents/planner.md) | strategist | phase 02, standalone implementation plans |
| [`reviewer`](../../.claude/agents/reviewer.md) | reviewer | phase 04, gate evidence and diff verdicts |

The executor tier is deliberately not a file: your main session in every
harness already plays it, per [AGENTS.md](../../AGENTS.md) and
[models/routing.md](../models/routing.md).

## How each harness reads them

| Harness | Path | Mechanism |
| --- | --- | --- |
| Claude Code | `.claude/agents/<name>.md` | canonical file, read natively |
| Copilot (CLI, VS Code) | `.claude/agents/<name>.md` | canonical file, read natively |
| OpenCode | `.claude/agents/<name>.md` | pointer: an `opencode.json` subagent whose `prompt` is `{file:./.claude/agents/<name>.md}` |
| Codex CLI | `.codex/agents/<name>.toml` | committed TOML generated by `scripts/sync.sh` |

OpenCode has no agent path setting, so `opencode.json` carries one hand-written
entry per role: `mode: "subagent"`, the frontmatter `description` repeated
verbatim, and a `{file:}` prompt pointing at the canonical file. Codex's
format is TOML rather than markdown, so it gets a generated file (with a "do
not edit" header). `scripts/sync.sh --check` fails CI when the TOML drifts
from `.claude/agents/` or an `opencode.json` description no longer matches
its agent's frontmatter.

## Authoring rules

1. **Frontmatter is the portable minimum**: `name` and `description` only.
   Every harness reads both; no harness chokes on the pair. Do NOT add
   `model`, `tools`, or `mode` keys: their value formats are per-harness and
   a shared file cannot carry per-harness values. Model assignment lives in
   [models/routing.md](../models/routing.md); tool restriction is a
   per-harness override a team applies in that harness's own config (for
   example the `permission` key of an `opencode.json` agent), never in the
   shared or generated files.
2. **The description is the trigger.** It states what the agent does and
   when to use it, because Claude Code and OpenCode auto-delegate based on
   descriptions. Write it with the same care as a skill description.
3. **The body is the role contract**: tier, phase, job, boundaries, links to
   the standards and skills it uses. Standalone and short (under ~60 lines):
   the agent may be spawned with nothing else in context.
4. **Adding an agent**: write `.claude/agents/<name>.md`; add the
   `opencode.json` entry (the same `description`, and
   `"prompt": "{file:./.claude/agents/<name>.md}"`); run `make sync` and
   commit the generated `.codex/agents/<name>.toml`; run
   `scripts/validate-agents.sh`, then PR per the loop.
5. Roles, not people-imitations. An agent file defines a job in the loop,
   never a persona with a name and a backstory.
